# F-002 — Log files in one place, rotated daily

Answers issue #3. Plan: `docs/specs/2026-11-07-go-rewrite-plan.md`. Builds on F-001 (console log lines) and F-008
(the service appends to `<data dir>\logs\printerone.log`).

## 0. Scope

Every run of PrinterOne — console or service — writes the same log file in one known folder, which can be read
while PrinterOne runs, rotates once a day and cleans itself up. Both editions, `internal/core/` (Go 1.10 subset).

## 1. Decisions

| # | Question | Answer |
|---|---|---|
| Q1 | Where, how many files, locked files (issue #3) | Decided by Claude on the owner's delegation (2026-11-07): one central folder, one current file shared by every session, daily rotation, readable while open, configurable folder — as in §2. |

## 2. Behaviour

- Folder: `<data dir>\logs` (F-001 §2.1 `<data dir>`), or `log.dir` from the config. It is created when missing.
- Config (optional; every key may be absent):

  ```json
  {"version": 2, "log": {"dir": "D:\\PrinterOneLogs", "keep_days": 30}, "printers": [...]}
  ```

  `log.dir` must be a non-empty string; `log.keep_days` an integer 1–3650 (default 30). Invalid → exit 2 naming the
  field (`log.dir`, `log.keep_days`), as F-001 §2.1.
- Current file: `printerone.log`. Every line of F-001 §2.5 (start-up lines and connection lines) is appended to it,
  by `serve` (which also keeps writing the console) and by `service run` (file only).
- Shared and readable: the file is opened for append for each line or kept open with sharing, so Notepad, `type`,
  `Get-Content -Wait` or a second PrinterOne process can read it while PrinterOne runs; two PrinterOne processes
  never corrupt each other's lines (each line is one write).
- Rotation: when the first line of a new local day is written, `printerone.log` is renamed
  `printerone-YYYY-MM-DD.log` (the date of the lines it holds) and a new `printerone.log` is started.
- Clean-up: at start-up and at each rotation, rotated files older than `keep_days` days are deleted. Other files in
  the folder are never touched.
- A failing log write (disk full, folder not writable) never stops PrinterOne; `serve` prints one warning to stderr
  the first time, with the path and the OS error.
- `printerone logs [--config p]` prints the absolute path of the current log file and exits 0 (it does not need a
  valid printer list, only a readable `log` section; with no config it prints the default path).
- The first start-up line of `serve` and `service run` names the log file path.

## 3. Out of scope

Log levels, JSON logs, Windows Event Log, size-based rotation, compressing old logs, a log viewer (F-005 shows the
live log in the web UI).

## Requirements

- **REQ-LOGF-001** Without `log.dir`, log files go to `<data dir>\logs`; the folder is created when missing.
- **REQ-LOGF-002** With `log.dir`, log files go to that folder.
- **REQ-LOGF-003** An invalid `log.dir` or `log.keep_days` (wrong type, empty, outside 1–3650) exits 2 naming the
  field; a missing `log` section is valid.
- **REQ-LOGF-004** `serve` appends every start-up and connection line to `printerone.log` and still prints them on
  the console.
- **REQ-LOGF-005** `service run` appends the same lines to the same `printerone.log`.
- **REQ-LOGF-006** While PrinterOne runs, another process can open and read `printerone.log`, and lines from two
  PrinterOne processes are never interleaved within a line.
- **REQ-LOGF-007** The first line written on a new local day renames `printerone.log` to
  `printerone-YYYY-MM-DD.log` with the previous lines' date and starts a new `printerone.log`.
- **REQ-LOGF-008** Rotated files older than `keep_days` days are deleted at start-up and at rotation; other files in
  the folder are kept.
- **REQ-LOGF-009** A failing log write does not stop PrinterOne, and `serve` warns once on stderr with the path and
  the OS error.
- **REQ-LOGF-010** `printerone logs` prints the absolute path of the current log file and exits 0, also with no
  config.
- **REQ-LOGF-011** The first start-up line of `serve` and `service run` names the log file path.
- **REQ-LOGF-012** The log code builds and its tests pass with Go 1.10.8.
