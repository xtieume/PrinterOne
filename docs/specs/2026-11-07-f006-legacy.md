# F-006 — Legacy edition for Windows XP to 8

Answers issue #7. Plan: `docs/specs/2026-11-07-go-rewrite-plan.md` (§1 Editions). Builds on every other feature: the
legacy edition is the same `internal/core` code, built with Go 1.10.8.

## 0. Scope

Deliver `PrinterOne-<version>-legacy-x86.exe` that runs on Windows XP SP3, Vista, 7 and 8 with the same functions as
the main edition, and prove it on real XP and Windows 7 machines.

## 1. Decisions

| # | Question | Answer |
|---|---|---|
| Q1 | XP support | A separate legacy build with Go 1.10.8 and the full feature set, including the web UI in IE6/IE8 (owner, 2026-11-07). |
| Q2 | When XP / Windows 7 are checked | Once, by the owner, after every feature is built (owner, 2026-11-07). |
| Q3 | Release packaging | Decided by Claude (2026-11-07): `scripts/build-release` builds the two main executables and the legacy one plus `SHA256SUMS`; a `v*` tag runs `.github/workflows/release.yml`, which publishes them as a draft release the owner reviews and publishes. CI runs the same script on every change to it (`release-build` check). |

## 2. Behaviour

- The legacy executable is built from `cmd/printerone-legacy` with Go 1.10.8 for `windows/386`; it shares every
  package of `internal/core`, and `printerone-legacy version` names the edition `legacy`.
- Differences from the main edition: 2 receive slots instead of 8 (32-bit memory). Nothing else.
- On Windows XP the data folder is `%ALLUSERSPROFILE%\Application Data\PrinterOne` (F-001 §2.1) and the firewall is
  managed with `netsh firewall` (F-008 §2.4).

## Requirements

- **REQ-LEGACY-001** `internal/core` and the legacy command build for windows/386 and pass their tests with Go 1.10.8.
- **REQ-LEGACY-002** The legacy edition receives at most 2 connections at once.
- **REQ-LEGACY-003** The legacy executable names its edition `legacy` in `version`.
- **REQ-LEGACY-004** On Windows XP SP3 the legacy exe lists printers, serves and prints a real job, installs and
  uninstalls the service with the firewall opening, and its web UI works in IE6 or IE8 (owner check).
- **REQ-LEGACY-005** On Windows 7 the same checks as REQ-LEGACY-004 pass, with IE8 or later (owner check).
