# F-004 — Per-printer IP allowlist

Answers issue #2. Plan: `docs/specs/2026-11-07-go-rewrite-plan.md`. Builds on F-003 (several printers).

## 0. Scope

Each printer can be limited to a list of client addresses. Both editions, `internal/core/`.

## 1. Decisions

| # | Question | Answer |
|---|---|---|
| Q1 | Allowlist or token (issue #2) | IP/CIDR allowlist per printer; no token on the RAW port, because RAW 9100 has no header and a token would break every standard printer driver (plan §1, owner, 2026-11-07). |
| Q2 | Details | Decided by Claude on the owner's delegation (2026-11-07), as in §2. |
| Q4 | Allowlist vs "not accepted until a slot frees" (F-001 REQ-RECV-007) | Decided by Claude (2026-11-07): a port with an allowlist accepts a client to check its address before it holds a slot, so a rejected client is closed at once even when every slot is busy; an allowed client then waits for a slot. At most one accepted connection per port waits this way, so resources stay bounded (≤ 32). Ports without an allowlist keep the slot-before-accept rule. |
| Q3 | Details from test design | Decided by Claude (2026-11-07): listeners stay IPv4 (`0.0.0.0`, F-001 §2.2), so IPv6 entries are accepted and matched by the receiver for a future dual-stack listener but no IPv6 client reaches `serve` today; `allow` of the wrong type (including `null`) exits 2 naming `printers[i].allow`; a CIDR with host bits set (`192.168.1.5/24`) means its block; IPv4 with leading zeros (`010.0.0.5`) is invalid in both editions; addresses never match across families; a client with no IP is refused; a non-empty list is shown on the start-up line as `allow: <items>`. F-005 later applies list changes without a restart. |

## 2. Behaviour

- Config: an optional `allow` list per printer entry; each item is an IPv4 or IPv6 address (`192.168.1.20`) or a
  CIDR block (`192.168.1.0/24`, `fd00::/8`).

  ```json
  {"name": "labels", "printer": "Zebra ZD420", "port": 9101, "allow": ["192.168.1.0/24", "10.0.0.5"]}
  ```

- `allow` missing → every client is allowed (as in F-001). `allow` present but empty → exit 2 naming
  `printers[i].allow` (an empty list would block everyone, which is never what the user meant).
- An item that is not a valid address or CIDR → exit 2 naming `printers[i].allow[j]`.
- An IPv4 client reaching a dual-stack socket as `::ffff:a.b.c.d` is matched as `a.b.c.d`.
- A client not in the list: the connection is closed at once without reading any byte, nothing is printed, it takes
  no receive slot for longer than the check, and it is logged as one line with `0B` and the result
  `rejected: not allowed`.
- Start-up lines show each printer's allowlist, or `allow: all`.
- Changing the list needs a restart (the service: `service install` again or a restart of the service).

## 3. Out of scope

Tokens, TLS, user accounts, deny lists, hostnames in the list, rate limits.

## Requirements

- **REQ-ALLOW-001** A printer without `allow` accepts every client.
- **REQ-ALLOW-002** A client whose address is listed, or inside a listed CIDR block, has its job printed.
- **REQ-ALLOW-003** A client outside the list is closed without any byte read, nothing is printed, and one line
  `0B "<printer>" rejected: not allowed` is logged.
- **REQ-ALLOW-004** IPv6 addresses and blocks match IPv6 clients; an IPv4-mapped IPv6 client matches the IPv4 entry.
- **REQ-ALLOW-005** An empty `allow` list exits 2 naming `printers[i].allow`.
- **REQ-ALLOW-006** An invalid item exits 2 naming `printers[i].allow[j]`.
- **REQ-ALLOW-007** Each printer's list applies only to its own port.
- **REQ-ALLOW-008** Start-up lines show each printer's list or `allow: all`.
- **REQ-ALLOW-009** The allowlist code builds and its tests pass with Go 1.10.8.
