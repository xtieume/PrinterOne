# F-008 — Windows service and firewall rule

Plan: `docs/specs/2026-11-07-go-rewrite-plan.md`. Builds on F-001 (`docs/specs/2026-11-07-f001-core.md`).

## 0. Scope

PrinterOne runs as a Windows service that starts with the machine, without anyone logging in, and opens its port in
the Windows Firewall. Both editions; all of it lives in `internal/core/` (Go 1.10 subset).

Not in F-008: log rotation and log settings (F-002), several printers (F-003 — the firewall rule already takes a port
list), a tray or UI control of the service (F-005).

## 1. Decisions

| # | Question | Answer |
|---|---|---|
| Q1 | Auto-start mechanism | Windows service only (owner, 2026-11-07). |

## 2. Behaviour

### 2.1 `printerone service install [--config p]`

1. Administrator rights are checked first: without them it prints `run as administrator` to stderr, changes
   nothing and exits 1.
2. The config is resolved and validated exactly as `serve` does (F-001 §2.1); an error exits 2 and changes nothing.
3. The service is created, or updated if it already exists (install is idempotent):
   name `PrinterOne`, display name `PrinterOne print server`, description
   `Receives RAW print jobs over TCP and prints them`, start type automatic, account LocalSystem, command line
   `"<absolute exe path>" service run --config "<absolute config path>"`.
4. The firewall rule is replaced: every existing PrinterOne rule is removed, then one inbound TCP allow rule for the
   configured port(s) is added (§2.4).
5. The service is started (or restarted when it was already running) and install waits until it reports running,
   at most 30 s; not running after 30 s counts as a start failure.
6. It prints `service PrinterOne installed and running` and exits 0.

If step 4 or 5 fails, install deletes a service it created in this run and removes the rule it added, prints the
Windows error and exits 1 (a service that already existed keeps its updated settings).

### 2.2 `printerone service uninstall`

Administrator check as in §2.1 (exit 1). Stops the service (waits until stopped, at most 30 s; longer, or a failing
delete, exits 1 with the Windows error), deletes it, removes
every PrinterOne firewall rule, prints `service PrinterOne removed` and exits 0. A service or rule that does not
exist is not an error (exit 0). The config file and log files are kept.

### 2.3 `printerone service run --config p`

- Started by the Service Control Manager. Started from a console it prints
  `service run is started by Windows; use serve to run in a console` and exits 2.
- Loads the config and runs the same receiver as `serve` (F-001 §2.2–2.3), with the same limits per edition.
- Connection lines (F-001 §2.5) and start-up lines are appended to `<data dir>\logs\printerone.log`; the folder is
  created when missing. A log write that fails does not stop the service.
- A config error or a busy port at start: the reason is appended to the log file and the service stops with a
  service-specific exit code (2 for config, 1 for the port), so `sc query PrinterOne` shows it.
- Stop and system shutdown requests: the service reports stop-pending (with wait hints while jobs are still being
  printed), stops accepting, drops connections still receiving, prints every fully received job, then reports
  stopped.

### 2.4 Firewall

netsh output is localized (Vietnamese, German… Windows), so PrinterOne never reads netsh *text* to decide; it uses
exit codes and port numbers only.

- Windows Vista and later: one rule named `PrinterOne`. Before removing, `netsh advfirewall firewall show rule
  name=PrinterOne` is run; exit 0 means the rule exists and `netsh advfirewall firewall delete rule
  name=PrinterOne` removes it (every rule of that name); a non-zero exit of `show` means there is no rule and nothing
  is deleted. Adding: `netsh advfirewall firewall add rule name=PrinterOne dir=in action=allow protocol=TCP
  localport=<ports>`.
- Windows XP (major version 5): `netsh firewall show portopening` lists the open ports; for each port to close that
  appears in that list, `netsh firewall delete portopening protocol=TCP port=<port>`. The ports to close are those of
  the config named in the installed service's command line; if that config cannot be read, uninstall prints a
  warning naming that config path and still exits 0. Install first closes the ports of the config named by an
  existing service, then opens each new port with `netsh firewall add portopening protocol=TCP port=<port>
  name=PrinterOne`.
- A non-zero exit of `add` or `delete` (or of XP `show`) is a failure reported with netsh's output.

### 2.5 Windows e2e (CI, `windows-latest`, runs as administrator)

Install with a temp config → the service is running → a job sent to the port reaches the printer's output file →
the log file has its connection line → uninstall → the service and the rule are gone.

## 3. Out of scope

Running as another account, recovery actions after a crash, several service instances, Windows Event Log, log
rotation (F-002).

## Requirements

- **REQ-SVC-001** Without administrator rights, `service install` and `service uninstall` print `run as
  administrator`, change nothing and exit 1.
- **REQ-SVC-002** `service install` with an invalid or missing config exits 2 and changes nothing.
- **REQ-SVC-003** `service install` creates service `PrinterOne` with the display name, description, automatic
  start, LocalSystem and the command line of §2.1.
- **REQ-SVC-004** `service install` on an existing service updates it to the §2.1 settings and exits 0.
- **REQ-SVC-005** `service install` replaces every PrinterOne firewall rule with one inbound TCP allow rule for the
  configured port.
- **REQ-SVC-006** `service install` starts the service, waits until it runs (at most 30 s), prints the success line
  and exits 0.
- **REQ-SVC-007** When adding the rule or starting the service fails, install removes the service it created and the
  rule it added, prints the Windows error and exits 1.
- **REQ-SVC-008** `service uninstall` stops and deletes the service, removes every PrinterOne rule, prints the
  success line and exits 0; a missing service or rule still exits 0; config and logs are kept.
- **REQ-SVC-009** `service run` started from a console prints the §2.3 message and exits 2.
- **REQ-SVC-010** Under the SCM, `service run` serves jobs with the F-001 receiver and edition limits.
- **REQ-SVC-011** Under the SCM, connection and start-up lines are appended to `<data dir>\logs\printerone.log`,
  creating the folder; a failing log write does not stop the service.
- **REQ-SVC-012** A config error or busy port under the SCM is written to the log file and the service stops with
  service-specific exit code 2 (config) or 1 (port).
- **REQ-SVC-013** A stop or shutdown request drops receiving connections, prints fully received jobs (reporting
  stop-pending meanwhile) and then reports stopped.
- **REQ-SVC-014** On Windows Vista and later the rule is checked with `show rule` (exit code), deleted only when it
  exists, and added with `netsh advfirewall` as in §2.4.
- **REQ-SVC-015** On Windows XP the ports are opened and closed with `netsh firewall portopening` as in §2.4;
  an unreadable config at uninstall gives a warning naming that config path and exit 0.
- **REQ-SVC-016** A failing `netsh add` or `delete` (or XP `show`) is reported with its output; a missing rule is
  never an error and no netsh text is parsed except port numbers on XP.
- **REQ-SVC-017** On a real Windows machine, install → print one job → uninstall works end to end (§2.5).
- **REQ-SVC-018** The service code builds and its tests pass with Go 1.10.8.
