# F-001 — Core: receive RAW over TCP and print

Plan: `docs/specs/2026-11-07-go-rewrite-plan.md`.

## 0. Scope

The smallest PrinterOne v2: one configured printer, RAW jobs over TCP, printed through winspool, run in a console.
Both editions (main and legacy) behave the same; all of it lives in `internal/core/` (Go 1.10 subset).

v2 is new software: nothing of v1 (Python) is read, migrated or cleaned up.

Not in F-001: Windows service, firewall rule and the service log file (F-008), several printers (F-003),
allowlist (F-004), log folder and rotation (F-002), web UI, API and tray (F-005), legacy packaging (F-006).

## 2. Behaviour

### 2.1 Config

- Lookup order: `--config <path>` → `config.json` next to the exe → `<data dir>\config.json`, where `<data dir>` is
  `%ProgramData%\PrinterOne` (Vista and later) or `%ALLUSERSPROFILE%\Application Data\PrinterOne` (XP, which has no
  `%ProgramData%`). `--config` naming a file that does not exist is an error; the lookup does not fall through.
- Format:

  ```json
  {"version": 2, "printers": [{"name": "default", "printer": "Canon MF220 Series", "port": 9100}]}
  ```

  `name` missing or empty → `default`; `port` missing → `9100`; unknown keys are ignored. F-001 accepts exactly one
  printer (F-003 lifts this).
- Errors exit with code 2, print one line to stderr and start nothing:
  - an unreadable file: the file path and the OS error;
  - bad JSON: the file path and the line:column of the error;
  - an invalid field — `version` not the number 2, `printers` missing / not a list / not exactly one entry, an
    entry not an object, `printer` missing / empty / not a string, `port` not an integer or outside 1–65535: the
    file path and the field (`printers[0].port`);
  - no config anywhere: the `<data dir>` path and the hint `printerone printers`.

### 2.2 Receiving

- Listens on TCP `0.0.0.0:<port>`. One job = every byte until the client closes its sending side (a full close
  or a half-close both end the job).
- Limit 256 MB = 268,435,456 bytes: a job of exactly that size is printed; one byte more → the connection is
  closed and nothing is printed.
- 60 s with no data from a connection (before the first byte or mid-job) → the connection is closed and nothing
  is printed.
- A client that resets or aborts mid-transfer → nothing is printed.
- A connection closed with 0 bytes → nothing is printed.
- A job is received completely (in memory) before it is printed, so a dropped job never reaches the printer.
- At most 8 connections are received at once in the main edition and 2 in the legacy edition (32-bit memory);
  further clients wait in the TCP backlog until a slot frees.
- Jobs for the printer are written one after another, never interleaved.
- Port already in use: exit 1 with a message naming the port. The process holding it is never touched.

### 2.3 Printing

- Each job is one document: `OpenPrinter` → `StartDocPrinter` (datatype `RAW`, document name
  `PrinterOne job from <client ip>`) → `StartPagePrinter` → `WritePrinter` until every byte is written →
  `EndPagePrinter` → `EndDocPrinter` → `ClosePrinter`. Bytes pass through unchanged.
- `printed` means the spooler accepted the whole job. A printer that is offline but installed queues the job in
  Windows; PrinterOne does not poll printer status.
- The printer is not checked at start-up. A failure of any call up to and including `EndDocPrinter` fails that
  job: after `StartDocPrinter`, `AbortPrinter` is called; `ClosePrinter` is always called once the printer was
  opened. A failing `ClosePrinter` after a successful `EndDocPrinter` does not fail the job (the spooler already
  holds it). The server keeps
  listening and the next job is printed normally.
- `printerone printers` prints each installed printer name on its own line and exits 0 (also when there are
  none); if the spooler cannot be queried it prints the Windows error to stderr and exits 1.

### 2.4 Commands (both editions)

| Command | Does |
|---|---|
| `printerone` (no args) | same as `serve` until the web UI arrives in F-005 |
| `printerone serve [--config p]` | foreground server |
| `printerone printers` | list installed printers |
| `printerone version` | prints `PrinterOne <version> (<edition>)`, exits 0 |

- `serve` on Ctrl+C: stops accepting, drops connections still receiving (logged `dropped: shutdown`), prints
  every job already fully received (the one being written and any waiting for the printer), exits 0. A second
  Ctrl+C exits 1 at once.
- `version` and `printers` never read the config, so they work with no config file.
- An unknown command, an unknown flag or a flag without its value prints the usage to stderr and exits 2.

### 2.5 Logging (console only until F-002/F-008)

- One line per connection on stdout:
  `<time RFC 3339, local> <client ip:port> <bytes>B "<printer>" <result>`, where `<bytes>` is the number of bytes
  received on that connection, `<printer>` is the config's `printer` value, and result is one of `printed`,
  `empty`, `dropped: too large`, `dropped: idle`, `dropped: reset`, `dropped: shutdown`,
  `failed: <windows error code> <message>`.
- Start-up lines (listening address, printer) go to stdout; start-up errors go to stderr.

### 2.6 Windows e2e check (CI)

Registry check `windows-e2e` on `windows-latest`: add a "Generic / Text Only" printer on a local port that writes
to a file, start `printerone serve`, send bytes to the port, compare the output file byte for byte. It is a
`gotest` check (`go test -tags e2e ./internal/core/e2e/...`).

## 3. Out of scope

Service, firewall and service log (F-008); several printers; allowlist; log files; web UI/API/tray; v1
compatibility; PDF conversion; killing the process on a busy port; LPD/IPP.

## Requirements

- **REQ-CFG-001** The config is read from `--config` when given (a missing file there is an exit-2 error naming
  the path), else `config.json` next to the exe, else `<data dir>\config.json`.
- **REQ-CFG-002** `<data dir>` is `%ProgramData%\PrinterOne`, or `%ALLUSERSPROFILE%\Application Data\PrinterOne`
  when `%ProgramData%` is not set (XP).
- **REQ-CFG-003** A valid file with one printer loads; an empty or missing `name` becomes `default`, a missing
  `port` becomes 9100, unknown keys are ignored.
- **REQ-CFG-004** An unreadable file exits 2 with the file path and the OS error; bad JSON exits 2 with the file
  path and the line:column; nothing listens.
- **REQ-CFG-005** Each invalid field listed in §2.1 exits 2 with the file path and the field name, and nothing
  listens.
- **REQ-CFG-006** No config anywhere exits 2 with the `<data dir>` path and the `printerone printers` hint.
- **REQ-RECV-001** A client that connects, sends bytes and closes causes exactly one job with exactly those bytes.
- **REQ-RECV-002** Two clients sending at once give two separate jobs, written to the printer one after the other.
- **REQ-RECV-003** A job of 268,435,456 bytes is printed; a job of 268,435,457 bytes is not, and its connection
  is closed.
- **REQ-RECV-004** A connection silent for 60 s, before or after its first byte, is closed and nothing is printed.
- **REQ-RECV-005** A connection reset mid-transfer prints nothing.
- **REQ-RECV-006** A connection closed with 0 bytes prints nothing.
- **REQ-RECV-007** No more than 8 connections (main) or 2 (legacy) are received at once.
- **REQ-RECV-008** A busy port exits 1 with a message naming the port; no other process is touched.
- **REQ-SPOOL-001** A job is one RAW document named `PrinterOne job from <client ip>` with every byte unchanged,
  written through the call sequence of §2.3.
- **REQ-SPOOL-002** A failing spooler call up to `EndDocPrinter` fails only that job: `AbortPrinter` after
  `StartDocPrinter`, `ClosePrinter` whenever opened, and the next job is printed; a failing `ClosePrinter` after a
  successful `EndDocPrinter` leaves the job printed.
- **REQ-SPOOL-003** `printers` prints one installed printer per line and exits 0, including with none; a spooler
  error exits 1.
- **REQ-CLI-001** `serve` (and no args) runs the server; Ctrl+C drops receiving connections, lets a printing job
  finish and exits 0; a second Ctrl+C exits 1 immediately.
- **REQ-CLI-002** `version` prints `PrinterOne <version> (<edition>)` and exits 0.
- **REQ-CLI-003** An unknown command, unknown flag or missing flag value prints the usage and exits 2.
- **REQ-LOG-001** Every connection writes exactly one line in the §2.5 format with the matching result.
- **REQ-E2E-001** On a real Windows spooler, bytes sent to the port arrive in the printer's output file unchanged.
- **REQ-RECV-009** A client that half-closes (shuts down its sending side, keeps the socket open) ends its job,
  and the job is printed.
- **REQ-CLI-004** `version` and `printers` work with no config file anywhere.
- **REQ-CLI-005** At the first Ctrl+C, a job fully received but still waiting for the printer is printed before
  `serve` exits 0.
- **REQ-LOG-002** A connection still receiving at the first Ctrl+C logs `dropped: shutdown` and prints nothing.
- **REQ-LEG-002** `internal/core` and the legacy command build, and their tests pass, with Go 1.10.8.
- **REQ-LEG-001** On Windows XP SP3 and Windows 7 the legacy exe runs `serve`, `printers` and prints one real job
  with the same results as the main exe.
