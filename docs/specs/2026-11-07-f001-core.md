# F-001 — Core: receive RAW over TCP and print (parity with v1)

Plan: `docs/specs/2026-11-07-go-rewrite-plan.md`.

## 0. Scope

The smallest PrinterOne v2 that replaces v1 on a server: one configured printer, RAW jobs over TCP, printed
through winspool, run in a console or as a Windows service, with the v1 `config.json` migrated. Both editions
(main and legacy) behave the same; all of it lives in `internal/core/` (Go 1.10 subset).

Not in F-001: several printers (F-003), allowlist (F-004), log rotation and log folder settings (F-002), web UI,
API and tray (F-005), legacy packaging (F-006).

| Q1 | Auto-start: Windows service, HKCU Run key (v1), or both? | Windows service only. The v1 Run key is dropped. |

## 2. Behaviour

### 2.1 Config

- Lookup order: `--config <path>` → `config.json` next to the exe (portable use) →
  `%ProgramData%\PrinterOne\config.json` (works for the service, which runs as LocalSystem).
- A file is v2 when it has `"version": 2`. Format (the `printers` field is a list so F-003 needs no second
  migration; F-001 accepts exactly one entry):

  ```json
  {"version": 2, "printers": [{"name": "default", "printer": "Canon MF220 Series", "port": 9100}]}
  ```

  `name` defaults to `default`, `port` to `9100`.
- v1 migration: a file without `version` that has `printer_name` is v1. When no v2 config exists, v1 files are
  read in this order: the `--config` path, `config.json` next to the exe, `%USERPROFILE%\PrinterOne\config.json`,
  `%APPDATA%\PrinterOne\config.json`. `printer_name` → `printer`, `port` → `port` (default 9100); every other v1 key
  is dropped. The v2 file is written where the lookup order would find it (the `--config` path when given, else
  next to the exe if the v1 file was there, else ProgramData), and the v1 file is renamed `config.v1.json` in its
  own folder. Migration happens once.
- Invalid config (bad JSON, missing or empty `printer`, port outside 1–65535, zero or more than one printer):
  the program exits with code 2 and a message naming the field; nothing listens.
- No config anywhere: exit code 2 with a message that shows the ProgramData path and the
  `printerone printers` command.

### 2.2 Receiving

- Listens on TCP `0.0.0.0:<port>`. One job = every byte until the client closes its side.
- Several clients may connect at once; jobs for the same printer are written one after another, never interleaved.
- A job larger than 256 MB: the connection is closed, nothing is printed, a log line says why.
- 60 s with no data from a connected client: the connection is closed, the partial job is dropped, logged.
- An empty connection (closed with 0 bytes) prints nothing and is logged.
- Port already in use: exit code 1 with an error that names the port. The process holding it is never touched.

### 2.3 Printing

- Each job goes to the printer as one document: `OpenPrinter` → `StartDocPrinter` (datatype `RAW`, document name
  `PrinterOne job from <client ip>`) → `WritePrinter` until every byte is written → `EndDocPrinter` →
  `ClosePrinter`. Bytes are passed through unchanged.
- The printer is not checked at start-up. A job whose printer is missing or fails is logged with the Windows error
  code and message; the server keeps listening.
- `printerone printers` lists the installed printer names, one per line, so the user can copy one into the config.

### 2.4 Commands (both editions)

| Command | Does |
|---|---|
| `printerone` (no args) | same as `serve` until the web UI arrives in F-005 |
| `printerone serve [--config p]` | foreground; Ctrl+C stops accepting, lets the job in progress finish, exits 0 |
| `printerone printers` | list installed printers |
| `printerone version` | print the build identity |
| `printerone service install [--config p]` | register the service and the firewall rule (admin) |
| `printerone service uninstall` | stop and remove the service and the firewall rule (admin) |
| `printerone service run --config p` | entry point used by the Service Control Manager |

An unknown command prints the usage and exits 2.

### 2.5 Service and firewall

- Service name `PrinterOne`, display name `PrinterOne print server`, start type automatic, account LocalSystem,
  command line `"<exe>" service run --config "<absolute config path>"`. `install` resolves the config first, so an
  invalid config fails the install.
- Firewall: `install` adds one inbound TCP allow rule named `PrinterOne <port>` for the configured port
  (`netsh advfirewall firewall` on Vista and later, `netsh firewall` on XP); `uninstall` removes it.
- Not elevated: install/uninstall exit 1 with a message saying to run as administrator; nothing is changed.
- A stop request: stop accepting, let the job in progress finish, report stopped within 10 s.
- LocalSystem sees printers installed for all users (local USB/LPT/TCP ports) but not per-user connections to
  printers shared by another PC; F-007 documents this.

### 2.6 Logging (minimal until F-002)

- One line per job: time, client IP:port, bytes, printer, result (`printed`, or why it was dropped or failed).
- `serve` writes to the console; the service appends to `%ProgramData%\PrinterOne\logs\printerone.log`.

### 2.7 Windows e2e check (CI)

A registry check `windows-e2e` runs on `windows-latest`: add a "Generic / Text Only" printer on a local port that
writes to a file, start `printerone serve`, send bytes to the port, and compare the output file byte for byte.
It is a `gotest` check (`go test -tags e2e ./internal/core/e2e/...`) so it can sit in a ledger.

## 3. Out of scope

Several printers, allowlist, log rotation, web UI/API/tray, the v1 Run-key auto-start, PDF conversion, killing
the process on a busy port, LPD/IPP.

## Requirements

- **REQ-CFG-001** The config is read from `--config` when given, else `config.json` next to the exe, else
  `%ProgramData%\PrinterOne\config.json`.
- **REQ-CFG-002** A v2 file with one printer loads with `name` defaulting to `default` and `port` to `9100`.
- **REQ-CFG-003** Bad JSON, an empty or missing `printer`, a port outside 1–65535, or zero or several printers
  make the program exit 2 with a message naming the field, and nothing listens.
- **REQ-CFG-004** With no v2 config, a v1 file (`printer_name`, `port`) found in the v1 places, in the order of
  §2.1, becomes a v2 file with one printer; other v1 keys are dropped.
- **REQ-CFG-005** After migration the v2 file sits where the lookup order finds it, the v1 file is renamed
  `config.v1.json`, and a second start does not migrate again.
- **REQ-CFG-006** No config anywhere: exit 2 with a message showing the ProgramData path and `printerone printers`.
- **REQ-RECV-001** A client that connects to the configured port, sends bytes and closes causes exactly one job
  with exactly those bytes.
- **REQ-RECV-002** Two clients sending at the same time produce two separate jobs, neither containing the
  other's bytes.
- **REQ-RECV-003** A job over 256 MB is dropped: the connection is closed and nothing is printed.
- **REQ-RECV-004** A client silent for 60 s mid-job is disconnected and its partial job is not printed.
- **REQ-RECV-005** A connection closed with 0 bytes prints nothing.
- **REQ-RECV-006** A busy port makes the program exit 1 with a message naming the port; no other process is touched.
- **REQ-SPOOL-001** A job is written as one RAW document named `PrinterOne job from <client ip>`, all bytes
  unchanged, through OpenPrinter / StartDocPrinter / WritePrinter / EndDocPrinter / ClosePrinter.
- **REQ-SPOOL-002** A spooler failure on one job is logged with the Windows error and the next job is still
  accepted and printed.
- **REQ-SPOOL-003** `printerone printers` prints each installed printer name on its own line.
- **REQ-CLI-001** `serve` stops on Ctrl+C after the job in progress finishes and exits 0; no args behaves as `serve`.
- **REQ-CLI-002** An unknown command prints the usage and exits 2.
- **REQ-SVC-001** `service install` registers service `PrinterOne` (automatic, LocalSystem) whose command line runs
  `service run` with the absolute config path, and adds firewall rule `PrinterOne <port>`.
- **REQ-SVC-002** `service uninstall` stops and removes the service and removes the firewall rule.
- **REQ-SVC-003** Without administrator rights, install and uninstall exit 1 with a message to run as
  administrator and change nothing.
- **REQ-SVC-004** A service stop request finishes the job in progress and the service reports stopped within 10 s.
- **REQ-LOG-001** Every job writes one log line with time, client IP:port, byte count, printer and result; the
  service writes to `%ProgramData%\PrinterOne\logs\printerone.log`.
- **REQ-E2E-001** On a real Windows spooler, bytes sent to the port arrive in the printer's output file unchanged.
- **REQ-LEG-001** The legacy exe runs `serve`, `printers` and `service install|uninstall` on Windows XP SP3 and
  Windows 7 with the same results as the main exe.
