# F-005 — Web UI and HTTP API (both editions)

Plan: `docs/specs/2026-11-07-go-rewrite-plan.md` (§1 UI rows). Builds on F-001, F-008, F-002, F-003, F-004.

## 0. Scope

A browser UI served by PrinterOne itself replaces the v1 desktop GUI. One set of pages for both editions; every
action works in Internet Explorer 6 with no JavaScript, and newer browsers get a nicer look and live updates. All
of it lives in `internal/core/` (Go 1.10 subset) and `static/`.

Not in F-005: the tray icon (F-009), packaging (F-006).

## 1. Decisions

| # | Question | Answer |
|---|---|---|
| Q1 | UI technology | One web UI for both editions, no native UI (owner, 2026-11-07). |
| Q2 | Two looks | Same functions; IE-era browsers get the minimal look, modern ones the nicer look (owner, 2026-11-07). |
| Q3 | Details | Decided by Claude on the owner's delegation (2026-11-07), as in §2. |
| Q4 | Details from test design | Decided by Claude (2026-11-07): a short `ui.password` is only an error when `remote` is on; an empty password field on the settings form keeps the stored password; a printer rename alone does not restart its listener; a save that is written but whose listener then fails to start stays saved and the page shows the error; a busy UI port exits 1 naming it; a printer port equal to the UI port is reported as `ui.port`; `/api/log?lines=` takes 1–1000, default 200; `allow: null` in the API means every client; the form token has at least 16 characters; the status page shows `allow: all`; the first save with no config writes `<data dir>\config.json`; "jobs today" and "last result" come from the receivers' connection results; the live log follows `printerone.log` across a rotation; the test page sends from 127.0.0.1 through the printer's port, and when the allowlist rejects it the page says so (the allowlist is never bypassed). |
| Q5 | Browser attacks on the local UI | Decided by Claude (2026-11-07): with remote off, a request whose Host is not `127.0.0.1:<port>` or `localhost:<port>` is refused with 403 (DNS rebinding); every response carries `X-Frame-Options: DENY` (clickjacking). |

## 2. Behaviour

### 2.1 Where it runs

- `serve`, `service run` and `printerone` with no arguments serve the UI on `http://127.0.0.1:<ui port>/`;
  `ui.port` in the config, default 9180, must differ from every printer port (exit 2 naming `ui.port`).
- `printerone` with no arguments also opens the default browser on that URL
  (`rundll32 url.dll,FileProtocolHandler <url>`, which works from XP to 11). If no config exists yet it starts with an
  empty printer list so the user can add the first printer in the UI (the receivers start once one is saved).
- Remote access: `ui.remote: true` binds `0.0.0.0` and requires `ui.password` (at least 8 characters, else exit 2
  naming `ui.password`); every request then needs HTTP Basic authentication with user `admin` and that password
  (IE6 supports it). Remote off (default): only `127.0.0.1` is bound and no password is asked.
- The config's `ui` section: `{"port": 9180, "remote": false, "password": "…"}`, all optional.

### 2.2 Pages

| Page | Shows | Actions (plain `<form method="post">`) |
|---|---|---|
| Status `/` | each printer: name, Windows printer, port, allowlist, jobs today, last result; the UI and log paths | — |
| Printers `/printers` | the list | add, edit, remove a printer (name, Windows printer chosen from the installed list or typed, port, allowlist as one address or CIDR per line) |
| Test `/test` | — | send a test page (a short text with the printer name and time) to a printer's port through the network path |
| Log `/log` | the last 200 lines of the current log file, newest last | refresh |
| Settings `/settings` | log folder, keep days, UI port, remote, password (never shown back) | save |

- Saving validates exactly like loading (F-001 §2.1, F-002, F-003, F-004 rules) and shows the same message next to
  the field; nothing is written when invalid. A valid save writes `config.json` atomically (temp file + rename),
  keeps unknown keys, and applies the change without restarting the process: listeners whose port, printer or
  allowlist changed are restarted, others keep running; jobs already received are still printed. A change of
  `ui.*` takes effect after a restart and the page says so.
- Every form carries a per-process random token; a POST without the matching token is refused with 403 (a page on
  another site cannot drive the local UI).
- All values shown are HTML-escaped.

### 2.3 Two looks, one function set

- Pages are rendered on the server with `html/template`. `base.css` uses only CSS that IE6 understands (tables,
  floats, no flexbox/grid). `modern.css` wraps all of its rules in `@supports (display: grid) { … }`, so IE and
  Chrome 49 / Firefox 52 on XP ignore it. `app.js` is loaded with `<script type="module">`, so those browsers never
  run it.
- `app.js` only enhances: the log page follows new lines live over Server-Sent Events, the status page refreshes
  counters, and forms submit without a full reload. It calls the same endpoints as the forms; there is no function
  only JS can reach.
- The files in `static/` are compiled into the binary through a generated Go file (Go 1.10 has no `embed`); a check
  fails when the generated file and `static/` differ.

### 2.4 HTTP API (JSON)

`GET /api/status`, `GET /api/printers`, `GET /api/installed-printers`, `POST /api/printers` (the whole list, same
validation as the form), `POST /api/test` (`{"name": …}`), `GET /api/log?lines=N` (N ≤ 1000), `GET /api/log/stream`
(SSE, one event per new line). Writes need the same token as the forms (header `X-PrinterOne-Token`) and, with remote
access on, Basic authentication. Errors: `{"error": "...", "field": "printers[1].port"}` with status 400.

## 3. Out of scope

User accounts, HTTPS, translations, statistics beyond today's job count, editing the config while the UI is open in
two browsers (last save wins).

## Requirements

- **REQ-UI-001** `serve`, `service run` and no-args serve the UI on `127.0.0.1:<ui.port>` (default 9180).
- **REQ-UI-002** `ui.port` equal to a printer port, or outside 1–65535, exits 2 naming `ui.port`.
- **REQ-UI-003** No arguments opens the default browser on the UI URL; with no config it starts with an empty
  printer list.
- **REQ-UI-004** With `ui.remote` on, the UI binds `0.0.0.0`, needs Basic auth `admin` / `ui.password`, and a
  password shorter than 8 characters exits 2 naming `ui.password`.
- **REQ-UI-005** The status page shows every printer's name, Windows printer, port, allowlist, jobs today and last
  result.
- **REQ-UI-006** A printer can be added, edited and removed with plain form posts, with no JavaScript.
- **REQ-UI-007** An invalid form is refused with the same message as config loading, shown next to the field, and
  nothing is written.
- **REQ-UI-008** A valid save writes `config.json` atomically and keeps unknown keys.
- **REQ-UI-009** A save restarts only the listeners whose port, printer or allowlist changed; received jobs still
  print.
- **REQ-UI-010** The test page sends a test job through the printer's port and it is printed.
- **REQ-UI-011** The log page shows the last 200 lines of the current log file.
- **REQ-UI-012** The settings page saves log and UI settings; the password is never sent back to the browser.
- **REQ-UI-013** A POST without the page's token is refused with 403.
- **REQ-UI-014** Every value from the config, the log or the request is HTML-escaped in pages.
- **REQ-UI-015** `base.css` uses no flexbox, grid or other CSS IE6 lacks; `modern.css` has every rule inside
  `@supports (display: grid)`; `app.js` is loaded only as `type="module"`.
- **REQ-UI-016** With JavaScript, the log page receives new lines live over SSE and forms submit without a reload,
  through the same endpoints as the forms.
- **REQ-UI-017** The generated asset file matches `static/`.
- **REQ-UI-018** The JSON API serves status, printers, installed printers, test and log as in §2.4, with the same
  validation, token and authentication rules as the forms.
- **REQ-UI-019** The UI code builds and its tests pass with Go 1.10.8.
- **REQ-UI-021** With remote off, a request whose Host header is not `127.0.0.1:<ui.port>` or `localhost:<ui.port>`
  is refused with 403.
- **REQ-UI-022** Every UI and API response carries `X-Frame-Options: DENY`.
- **REQ-UI-020** In IE6/IE8 on XP and in a current browser, every page works and looks right (owner check).
