# Harness for PrinterOne

Source: the LaunchPadTV harness (`docs/specs/2026-11-02-harness.md` in that repo), adapted on 2026-11-07 for a
public Go repository with base branch `master`. Goal: every change goes from spec to code, and an agent starts a
task already knowing the project structure and the rules of the exact area it edits.

## 1. Decisions (2026-11-07)

| Topic | Decision |
|---|---|
| Three layers | Path-scoped rules `.claude/rules/` (what is right), skills `.claude/skills/` (how), roles `.claude/agents/` (who, and what they hand back). `CLAUDE.md` is a short map. |
| Engine | goalrun from the `testcase` plugin (`xtieume/testcase`), pinned in `.harness/profile.json`; CI fetches that commit. **Never copied into this repo.** |
| Script | `scripts/harness` keeps only what skills and goalrun cannot do: `check`, `rules-for`, `lint-rules`, `spec-gate`, `accept`. |
| Check kinds | `gotest` (reads `go test -json`), `unittest` (the self-test), `exit`. The LaunchPadTV kinds (gradle, bats, node-check, Maestro device) are dropped. |
| Go 1.10 | `scripts/go110` runs Go 1.10.8 in Docker (GOPATH layout) for `internal/core/` and the legacy command. |
| Acceptance | Receipt in Git (`.harness/acceptance/<F>/`), written when the owner merges the PR (or comments `/accept <run> <sha7>`) and CI `verify` for that head is green. |
| Hook | `.claude/settings.json` + `.harness/hooks/guard.py`: deny push/merge of `master`/`main`; ask before a release, a tag push, a force push, or any public comment/close/edit on issues and PRs, and any `gh api` write. |
| Secrets | The repo is public and holds no secrets. The LaunchPadTV secret-file guard is dropped. |
| Issues | `features.json` entries carry `issues: [N, …]`; skill `open-pr` writes `Closes #N`. `lint`/`spec-gate` validate the shape only (no network). |
| Branch protection | Not configured; `accept` refuses when CI is not green; the owner checks `Verify` before merging. |

## 2. Parts

```
.claude/rules/       00-project-overview, 01-go-code, 02-testing, 03-git-release (more added with the code they govern)
.claude/skills/      implement-feature, fix-bug, review-change, open-pr (release added in phase 5)
.claude/agents/      implementer, test-writer, reviewer
.claude/settings.json + .harness/hooks/guard.py
.githooks/pre-push   refuses master/main for every client
.agents/skills       symlink to .claude/skills for Codex
.harness/profile.json   check registry (id → fixed argv), goalrun pin, product_paths, approvers
.harness/features.json  features with revisions: behavior, spec, acceptance, allowed_paths, required_checks, risk, issues
.harness/acceptance/    receipts
.harness/tests/         self-test (throwaway git repos with seeded faults)
scripts/harness, scripts/go110
.github/workflows/verify.yml
```

Run ids: `F-00N-r<rev>` for a feature revision, `F-00N-r<rev>-bug-<name>` for a bug fix on an accepted revision.

## 3. Flow

- **Feature / spec change** (skill `implement-feature`): branch → spec with the owner's answers and atomic REQs →
  `features.json` entry → commit → goalrun init → docs-review → testcase (tests red first) → ledger → code →
  review → breaks for rows green before the code → goalrun `--verify` on the commit → PR with `Feature: F-00N`
  and `Closes #N` → owner signs MANUAL rows → `--verify` exit 0 → owner merges → `harness accept` → receipt PR.
- **Bug kind 1** (skill `fix-bug`, spec already right): run `-bug-<name>`, `reqs.txt` only REQs from the receipt,
  reproducing test red first, PR `Feature: F-00N bug <name>`, spec and revision unchanged.
- **Bug kind 2** (spec silent): the owner decides the behaviour → feature flow with revision+1.

## 4. Requirements

- **REQ-HAR-003** `check <id>` only runs the registry argv; an unknown id, `--tests` on a check without a filter,
  or a filter that fails its regex → ERROR, nothing runs.
- **REQ-HAR-004** A missing tool or 0 tests run → ERROR.
- **REQ-HAR-005** `gotest`: any failing test → FAIL; non-zero exit with no failing test (build error, vet, panic,
  Docker failure) → ERROR, except on a check marked `build_error_fails` (`core-go110`), where it is FAIL because
  not building under Go 1.10 is the defect that check exists for; no passing test → ERROR. `unittest`: failures → FAIL, load/compile error → ERROR.
- **REQ-HAR-006** Secret-looking environment variables never reach a check; token-like strings in output are masked.
- **REQ-HAR-012** `accept` refuses (STALE) without a current whole-ledger proof on the current commit.
- **REQ-HAR-013** `accept` refuses (ERROR) when a break crashed the check (`HARNESS-RESULT: ERROR` in mutation
  evidence) instead of failing a test.
- **REQ-HAR-017** `accept` writes a receipt only when the PR was merged by a login in `approvers`, or carries an
  `/accept <run> <sha7>` comment from one matching the head (all comment pages read).
- **REQ-HAR-018** A receipt records feature, revision, run, spec + sha256, `reqs`, base/head SHA, dependency
  receipts, evidence (goalrun proof, CI run URL), approval, MANUAL rows (sha256 of their text), time.
- **REQ-HAR-022** `verify.yml` runs on every PR into `master`: `lint-rules`, `spec-gate`, the checks whose `paths`
  changed (+ `always_checks`, same glob matching as `scripts/harness`), and one summary job `verify`.
- **REQ-HAR-030** `rules-for <path…>` prints the unconditional rules plus every rule whose glob matches; a missing
  path → ERROR unless `--allow-missing`.
- **REQ-HAR-031** `lint-rules` FAILs when a rule lacks `description`, a glob matches no tracked file, a named
  skill/role/rule does not exist, a backticked path does not exist, `CLAUDE.md` > 120 lines, `AGENTS.md` > 40 lines.
- **REQ-HAR-033** The hook (commands split into simple commands, heredoc bodies dropped, quoting respected) denies
  a push to `master`/`main` (including line continuations, a bare `git push` or `git push origin HEAD` while on
  `master`, `gh api …/pulls/N/merge`) and `git merge` while on `master`; it asks before `gh release
  create|upload|edit|delete`, a tag push, a force push, `gh issue comment|close|edit|create|reopen|lock`,
  `gh pr comment|close|review`, `gh repo edit|delete` and any `gh api` write. `.githooks/pre-push` refuses
  `master`/`main` for every client; `.agents/skills` points at `.claude/skills`.
- **REQ-HAR-034** An automated ledger row is exactly `scripts/harness check <id> [--tests <filter>]` and re-quotes
  to the same text; `exit` checks are not allowed in a ledger. `accept` enforces it.
- **REQ-HAR-035** `spec-gate`: files in `product_paths` must sit in the `allowed_paths` of the feature the PR body
  declares, unless a `Spec-Exempt: <reason>` line is present (the file list is printed); a new revision with an
  unchanged spec → FAIL.
- **REQ-HAR-036** The spec of an accepted revision cannot change without a revision bump; receipts are append-only
  and must be valid JSON; moving `spec` to another file without a bump → FAIL.
- **REQ-HAR-037** A `bug` line keeps spec and revision, and the revision must already have a receipt;
  `accept --bug` FAILs when `reqs.txt` names a REQ the receipt lacks.
- **REQ-HAR-038** A receipt counts only with every field, an approver, a `run_id` matching feature/revision, and
  `head_sha` (or `approval.merge_commit` after a squash/rebase merge) an ancestor of HEAD.
- **REQ-HAR-039** `accept` uses only the latest `verify` run for the head; the PR is open or merged into `master`.
- **REQ-HAR-040** An unexpected crash in the harness is ERROR, never FAIL.

Each REQ has a test with its id in `.harness/tests/test_harness.py`.

## 5. Verification

- Self-test: `scripts/harness check harness-selftest` (33 tests: throwaway git repos, real goalrun, a real
  `go test` fixture).
- Phase 0 baseline on the harness branch (2026-11-07): `go-test` PASS (1 test), `go-vet` PASS, `win-build` PASS,
  `core-go110` PASS (Go 1.10.8, legacy exe built for windows/386), `harness-selftest` PASS (33 tests).

## 6. Out of scope

- No automatic merge, release, tag or GitHub comment, even when every gate is green.
- CI does not re-run the mutation proof; the proof is the local goalrun `--verify` on the exact commit.
- The registry limits commands; it is not a sandbox.
